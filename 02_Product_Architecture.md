# Product Architecture

## Architecture Mode

Tool Mode

## Core Product Flow

Landing → Input → Processing → Result → Download

## Required Screens

1. Landing Page
2. Audit Input
3. Processing Screen
4. SEO Verdict Result
5. Blueprint Delivery

## Landing Page

Purpose:
Explain the product and convert the visitor into the audit flow.

Primary CTA:
Start SEO Blueprint

Content blocks:
- pain statement
- what the scan detects
- what the user receives
- public GitHub reference
- pricing access

## Audit Input

Required fields:
- store URL
- store type
- platform
- monthly traffic range
- primary goal
- known issue

Validation rules:
- URL required
- platform optional
- goal required
- no long form friction

## Processing Screen

Purpose:
Create perceived analysis depth while keeping the system simple.

Processing states:
- detecting site structure
- checking content clarity
- evaluating SEO signals
- preparing blueprint
- finalizing download package

## Result Screen

Result sections:
- Executive verdict
- SEO priority score
- critical issue
- recommended first fix
- risk if ignored
- download action

## Delivery Layer

The delivery layer provides the 8-file package:

- Executive Blueprint
- Product Architecture
- Technical Stack
- Supabase Schema
- Execution Roadmap
- PROM MAX PRO Execution
- Launch System
- Build Guide

## Data Flow

User Input → Mode Detection → Score Engine → Result Engine → Package Builder → ZIP Download

## MVP Boundary

The MVP must not become a full SEO suite.

The MVP wins by giving users a clear fix order.

## Expansion Later

Only after validation:

- saved reports
- agency accounts
- white-label exports
- historical scans
- client portal
- advanced integrations
